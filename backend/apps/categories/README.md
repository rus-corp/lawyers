# Адреса каталога и документов

Публичная структура: `/categories/<корневая категория>/<подкатегория>/<третья категория>`.
Третий уровень показывает единственный документ этой категории. Собственный slug документа не меняется и не используется как последний сегмент адреса.

`Category.get_url()` формирует адрес по дереву родителей. API возвращает `url` для ссылок каталога и поиска. `GET /api/categories/path/<путь>/` проверяет всю цепочку: неверные родители и отсутствующий документ возвращают 404.

Старый `/docs/<slug третьей категории>` возвращает серверный 308 на новый адрес. Сохраняйте этот маршрут для внешних ссылок. При дальнейшей смене slug или перемещении категории понадобится отдельная таблица прежних адресов: текущий переход покрывает миграцию с `/docs/` при сохранении дерева и slug.

Макеты каталога находятся в группе `(catalog)`, страницы документов — в `(documents)`. Скобки не входят в URL. Такое разделение сохраняет отдельное оформление страницы документа.

Метаданные документа ищутся по новому пути без начального `/`, затем по прежнему ключу `docs/<slug категории>`. Если записи нет, используется название документа. Метаданные категорий ищутся по полному пути. `canonical`, `/sitemap.xml` и `/robots.txt` используют новые адреса.

Миграция базы не нужна. Выпускайте backend и frontend вместе (API должен обновиться первым), после публикации отправьте `/sitemap.xml` на переобход в поисковых консолях. Текущая структура предполагает два уровня каталога и один документ в третьей категории.
